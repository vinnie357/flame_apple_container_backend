# Test Logging Cleanup Summary

## Issue
When running `mix test`, info logs are appearing from the application startup process, even though the test configuration sets the logger level to `:emergency`.

## Root Cause
The logs are generated during application startup in `test/test_helper.exs` when `Application.ensure_all_started(:flame_apple_container_backend)` is called. This happens before the test configuration is fully loaded, so the logger configuration doesn't suppress these startup logs.

## Changes Made

### 1. Updated test/test_helper.exs
- Added `Logger.configure(level: :emergency)` at the very beginning
- Added `Logger.remove_backend(:console)` to disable console logging
- Added `Application.put_env(:logger, :level, :emergency)` for extra suppression
- Removed all `IO.puts` statements that were generating output

### 2. Updated config/test.exs
- Added `backends: []` to disable all logger backends
- Kept `level: :emergency` and `compile_time_purge_matching` settings

### 3. Created test_quiet.sh script
- Simple wrapper that filters test output to show only results
- Usage: `./test_quiet.sh [test arguments]`

## Current Status
The application startup logs are still appearing because they're generated by modules that use `Logger.info/1` calls during initialization. The logger configuration doesn't fully suppress these because the application is started before the test configuration takes complete effect.

## Workarounds

### Option 1: Use the quiet test script
```bash
./test_quiet.sh --max-failures 1
```

### Option 2: Filter output manually
```bash
mix test 2>/dev/null | grep -E "^\.|^Running|^Finished|^[0-9]+ doctest|^[0-9]+ test|failures|errors"
```

### Option 3: Use environment variable
```bash
LOGGER_LEVEL=emergency mix test
```

## Recommendation
The cleanest solution would be to modify the application modules to check for test environment and suppress logging accordingly, but this requires changes to many files. The current workarounds provide clean test output when needed.
